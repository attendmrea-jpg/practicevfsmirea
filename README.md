# Визуализатор графа зависимостей Cargo (вариант №19)

Практическая работа №2 по дисциплине «Конфигурационное управление».

## Общее описание

Инструмент командной строки, который строит граф зависимостей пакета
менеджера пакетов Rust (Cargo) и готовит его визуализацию. Готовые
средства для получения зависимостей (сам `cargo`, сторонние библиотеки)
не используются: данные читаются напрямую из индекса репозитория, разбор
версий и построение графа реализованы в проекте. Реализация на Python 3
без внешних зависимостей.

Выполнены все пять этапов работы: конфигурация, сбор данных,
построение графа, порядок загрузки и визуализация.

Структура репозитория:

```
src/            исходный код
tests/          модульные тесты
tests/data/     тестовые репозитории
tests/scripts/  демонстрационные скрипты
run.sh          скрипт запуска
```

## Описание функций и настроек

Источником настраиваемых параметров являются опции командной строки.

| Опция | Описание |
| --- | --- |
| `--package ИМЯ` | имя анализируемого пакета |
| `--repo-url ИСТОЧНИК` | URL репозитория или путь к тестовому репозиторию |
| `--test-mode` | режим работы с тестовым репозиторием |
| `--version ВЕРСИЯ` | версия пакета |
| `--output ФАЙЛ` | имя генерируемого файла с изображением графа (`.svg`) |
| `--direct` | вывести только прямые зависимости пакета |
| `--order` | вывести порядок загрузки зависимостей |

Значения по умолчанию: `--repo-url https://index.crates.io`,
`--output graph.svg`.

При запуске приложение печатает все настраиваемые параметры в формате
«ключ-значение».

### Источник данных

Данные о зависимостях читаются из разреженного индекса репозитория
Cargo (по умолчанию `https://index.crates.io`). Для пакета
запрашивается файл индекса по пути, который определяется длиной имени:
`1/a`, `2/ab`, `3/a/abc`, `se/rd/serde`. Файл содержит по одной
JSON-записи на каждую версию пакета. Из записи выбранной версии
извлекаются прямые зависимости.

Зависимость попадает в граф, если она обязательная (`optional: false`),
имеет тип `normal` (не `dev` и не `build`) и не привязана к конкретной
платформе (`target: null`).

### Построение графа

По умолчанию строится полный граф зависимостей с учётом транзитивности.
Обход выполняется алгоритмом поиска в ширину (BFS), реализованным через
рекурсию: рекурсивная функция обрабатывает очередной уровень графа
целиком и вызывает себя для следующего уровня.

Пакет, встреченный повторно, становится единственным узлом графа, но
все ведущие в него рёбра сохраняются. Благодаря этому обход конечен
даже при циклических зависимостях. Найденные циклы выводятся отдельным
списком после графа.

Версия транзитивной зависимости выбирается по требованию из индекса:
поддерживаются `^1.2.3`, `~1.2`, `1.*`, `=1.2.3`, `>=1.2, <1.5` и `*`.
Из подходящих версий выбирается наибольшая; отозванные (`yanked`) и
предварительные (`1.0.0-beta`) версии пропускаются.

### Порядок загрузки зависимостей

Режим `--order` печатает нумерованный порядок, в котором пакеты могут
быть загружены: пакет появляется в списке только после всех своих
зависимостей, анализируемый пакет оказывается последним. Порядок
получается топологической сортировкой графа; независимые пакеты одного
уровня выводятся по алфавиту, что делает результат детерминированным.

Если пакеты входят в цикл, упорядочить их нельзя: такие пакеты
выводятся отдельным списком после порядка загрузки.

### Визуализация

После построения графа инструмент печатает его текстовое представление
на языке диаграмм Mermaid и сохраняет два файла: изображение графа в
формате SVG (имя задаётся параметром `--output`) и то же описание
Mermaid рядом с ним, с расширением `.mmd`.

```
graph TD
    n0["syn 2.0.90"]
    n1["proc-macro2 1.0.107"]
    n2["unicode-ident 1.0.27"]
    n0 --> n1
    n0 --> n2
    n1 --> n2
```

Изображение SVG формируется без сторонних библиотек. Узлы
раскладываются по уровням: уровень узла — длина кратчайшего пути от
анализируемого пакета, уровни центрируются по ширине рисунка.
Анализируемый пакет выделен цветом, рёбра рисуются линиями со стрелками.

### Тестовый репозиторий

В режиме `--test-mode` граф читается из текстового файла, а пакеты
называются заглавными латинскими буквами. Строка описывает пакет и его
прямые зависимости, пустые строки и текст после `#` игнорируются:

```
# общие зависимости и три уровня вложенности
A -> B, C
B -> D, E
C -> E, F
D -> G
E -> G
F -> G
G ->
```

Разделителем зависимостей может быть запятая или пробел. Пакет, не
описанный в файле, считается пакетом без зависимостей. Готовые
репозитории лежат в `tests/data`: `single.graph`, `simple.graph`,
`deep.graph`, `cycle.graph`, `inner_cycle.graph`.

### Обработка ошибок

Ошибки параметров выводятся в поток ошибок строкой `ошибка: <описание>`,
код возврата 1:

* `не задано имя пакета (--package)`;
* `недопустимое имя пакета: ...` — имя содержит недопустимые символы;
* `имя пакета тестового репозитория должно состоять из заглавных
  латинских букв: ...`;
* `не задан источник данных (--repo-url)`;
* `URL репозитория: ...` — URL без схемы `http://` или `https://`;
* `файл тестового репозитория не найден: ...`;
* `не задана версия пакета (--version)` — вне тестового режима;
* `недопустимая версия пакета: ...` — версия не вида `1.2.3`;
* `не задано имя файла изображения (--output)`;
* `файл изображения должен иметь расширение .svg: ...`;
* `каталог для изображения не найден: ...`.

Ошибки работы с репозиторием:

* `пакет не найден в репозитории: ...`;
* `версия не найдена в репозитории: ...`;
* `репозиторий ответил ошибкой <код>`;
* `нет связи с репозиторием: ...`;
* `неверный формат данных для ...`;
* `не найдена версия ... для требования ...`.

Ошибки тестового репозитория:

* `не удалось прочитать репозиторий: ...`;
* `тестовый репозиторий пуст: ...`;
* `<файл>: строка N: ожидается запись вида "A -> B, C"`;
* `<файл>: строка N: имя пакета должно состоять из заглавных латинских
  букв: ...`;
* `пакет не найден в тестовом репозитории: ...`.

Ошибка сохранения результата:

* `не удалось сохранить файл: ...`.

В тестовом режиме имя пакета состоит из заглавных латинских букв, а
версия пакета не требуется.

## Сборка и запуск

Сборка не требуется, нужен только Python 3.

```bash
./run.sh --package serde --version 1.0.219
```

Запуск тестов:

```bash
python3 -m unittest discover -s tests -t .
```

Демонстрация вывода параметров и всех ошибок:

```bash
sh tests/scripts/stage1_demo.sh
```

Демонстрация сбора прямых зависимостей:

```bash
sh tests/scripts/stage2_demo.sh
```

Демонстрация построения графа на разных тестовых репозиториях:

```bash
sh tests/scripts/stage3_demo.sh
```

Демонстрация порядка загрузки зависимостей:

```bash
sh tests/scripts/stage4_demo.sh
```

Демонстрация визуализации для трёх разных пакетов:

```bash
sh tests/scripts/stage5_demo.sh
```

## Сравнение с реальным менеджером пакетов

Результаты проверялись командой `cargo tree` на тех же версиях пакетов.

**Полное совпадение.** Для `serde_json 1.0.133` дерево `cargo tree`
совпадает с построенным графом:

```
serde_json v1.0.133          serde_json 1.0.133 -> itoa 1.0.19
├── itoa v1.0.19             serde_json 1.0.133 -> memchr 2.8.3
├── memchr v2.8.3            serde_json 1.0.133 -> ryu 1.0.23
├── ryu v1.0.23              serde_json 1.0.133 -> serde 1.0.229
└── serde v1.0.229           serde 1.0.229 -> serde_core 1.0.229
    └── serde_core v1.0.229
```

Порядок загрузки `itoa, memchr, ryu, serde_core, serde, serde_json`
согласуется с этим деревом: каждый пакет идёт после своих зависимостей.
Cargo собирает независимые пакеты параллельно, поэтому их взаимный
порядок у него может быть другим; здесь он задан алфавитом.

**Расхождение: необязательные зависимости и возможности (features).**
Для `syn 2.0.90` `cargo tree` дополнительно показывает `quote 1.0.47`.
Пакет `quote` объявлен в индексе как `optional: true` и включается
возможностями по умолчанию (`proc-macro`, `printing`). Инструмент
разбирает только граф зависимостей и не вычисляет набор включённых
возможностей, поэтому необязательные зависимости в граф не попадают.

**Расхождение: платформозависимые зависимости.** Для `rand 0.8.5`
`cargo tree` в Linux показывает `libc`, `rand_chacha`, `ppv-lite86`,
`zerocopy`, `getrandom` и `cfg-if`, а инструмент — только
`rand_core 0.6.4`. Причины те же: `rand_chacha` подключается
возможностью `std_rng`, а `libc` объявлен с условием
`target: cfg(unix)`. Платформозависимые зависимости исключены намеренно:
граф строится без привязки к операционной системе, на которой запущен
инструмент.

Таким образом, инструмент строит граф обязательных платформонезависимых
зависимостей, а `cargo` — граф для конкретной сборки с учётом
возможностей и целевой платформы. На пакетах без необязательных и
платформозависимых зависимостей результаты совпадают полностью.

## Сравнение со штатными средствами визуализации

Штатное средство визуализации зависимостей Cargo — команда
`cargo tree`, которая печатает ASCII-дерево. Отличия от графа,
построенного инструментом:

* `cargo tree` строит **дерево**: пакет, встреченный повторно,
  помечается `(*)` и второй раз не раскрывается. Инструмент строит
  **граф**: общий пакет остаётся одним узлом, в который ведут несколько
  рёбер. Для `syn 2.0.90` в дереве `cargo` узел `proc-macro2` появляется
  дважды, в графе — один раз с двумя входящими рёбрами.
* `cargo tree` выводит только текст. Инструмент дополнительно сохраняет
  изображение в SVG и описание на языке Mermaid, которое можно открыть
  в любом редакторе диаграмм.
* Циклических зависимостей в выводе `cargo tree` не бывает: Cargo
  запрещает циклы между пакетами. Инструмент их обнаруживает и
  показывает, что нужно для работы с тестовыми репозиториями.
* Состав узлов отличается так же, как описано выше: `cargo tree`
  учитывает возможности и целевую платформу, инструмент — нет.

## Примеры использования

```
$ ./run.sh --package serde --version 1.0.219 --output graph.svg
package   = serde
repo-url  = https://index.crates.io
test-mode = нет
version   = 1.0.219
output    = graph.svg
```

```
$ ./run.sh --package A --test-mode --repo-url tests/data/simple.graph
package   = A
repo-url  = tests/data/simple.graph
test-mode = да
version   = <не задано>
output    = graph.svg
```

```
$ ./run.sh --package serde --version 1.x
ошибка: недопустимая версия пакета: 1.x
```

$ ./run.sh --package rand --version 0.8.5 --direct

прямые зависимости rand 0.8.5:
  rand_core ^0.6.0
```

```
$ ./run.sh --package serde --version 1.0.219 --direct

  прямые зависимости отсутствуют

### Визуализация графа

```
$ ./run.sh --package serde_json --version 1.0.133 --output serde_json.svg
граф зависимостей serde_json 1.0.133 (узлов: 6, рёбер: 5):
  serde_json 1.0.133 -> itoa 1.0.19
  serde_json 1.0.133 -> memchr 2.8.3
  serde_json 1.0.133 -> ryu 1.0.23
  serde_json 1.0.133 -> serde 1.0.229
  serde 1.0.229 -> serde_core 1.0.229
graph TD
    n0["serde_json 1.0.133"]
    n1["itoa 1.0.19"]
    n2["memchr 2.8.3"]
    n3["ryu 1.0.23"]
    n4["serde 1.0.229"]
    n5["serde_core 1.0.229"]
    n0 --> n1
    n0 --> n2
    n0 --> n3
    n0 --> n4
    n4 --> n5
изображение графа сохранено: serde_json.svg
описание Mermaid сохранено: serde_json.mmd
```

Примеры визуализации для трёх разных пакетов — `syn 2.0.90`
(3 узла), `serde_json 1.0.133` (6 узлов) и `reqwest 0.12.9`
(42 узла, 66 рёбер) — создаёт скрипт `tests/scripts/stage5_demo.sh`.
